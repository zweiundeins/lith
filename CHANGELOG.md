# Changelog

Until 1.0, a minor release may change the API; its entry says what to change in an app.

## Unreleased

- `events`: a new package for event sourcing on the writer. A command calls `Execute` in its `Apply`: it reads the stream's state row, which a `Decider` folds from the stream's own events, checks the expected version (`Any`, `NoStream`, `Exactly`, or `ErrConflict`), decides, appends, saves the row and runs the inline projectors (`Handle`), all in the command's savepoint. Streams are typed by their key, `int64` or `string`, and their events' interface; each event type is defined once with `Define`, through a helper of one line per stream that makes the compiler check that the type belongs to it. Events record their time in Unix milliseconds, an actor, a correlation and a causation. `Append` and `One` append without a decision; `Load` and `Since` read as iterators over any `sqlite.Querier`; `Upcast` reads an old event type as a new one. `New` refuses a projector that neither handles nor ignores a type of its stream, and duplicate names. A `Runner` rebuilds an inline projector whose version changed into copies of the tables it names (`Tables`), a command per batch, and swaps them in with the last batch, so pages never read a table half built; a decider whose `Version` changed folds each stream again at its next command. Catch-up projectors (`After`) run after the commit from a checkpoint, woken by the writer, with the event's position as the idempotency key; an event that keeps failing parks the projector with its error in `Runner.Stats`. `Forget` and `Prune` delete events, and positions, from `AUTOINCREMENT`, are never handed out again. The tables `lith_events`, `lith_event_state` and `lith_projections` are created by the first command that needs them. `events/eventstest` tests a decider as given, when, then, and checks a JSON sample of every event type. Through the writer with one inline projector, it appended 18,342 events a second with 200 producers and NORMAL (`bench/RESULTS.md`).
- `writer`: `Tx.Local` and `Tx.SetLocal` keep a value per writer, for packages built on it that serve many databases, such as what `events` knows of each.
- Docs and skill: the guide Event sourcing; the commands guide's event-sourced command and the board example run on `events`, and the review checklist has a section on events.
- Template: the Caddy block is `deploy/app.caddy`, for `/etc/caddy/sites/`, and `deploy/observability` holds the app's blackbox probes and an Alloy file that ships its journal, with slog's level as a label, and its access log to Loki. `deploy/setup-host.sh` installs them into the folders a shared host's Prometheus and Alloy load, each only where that service is installed, and reloads Alloy, putting the old file back if Alloy refuses the new one. The CI deploy key is now optional. The guide Metrics and monitoring lists the folders and the labels; an app made from an earlier template can copy the folder and the script.
- `lith-new`: `app_` in the template becomes the app's name with `-` as `_`, for identifiers such as Alloy's component labels.
- The Grafana dashboard and alert rules for lith apps moved from `site/deploy/observability` to `deploy/observability` at the repository's root, with a README on installing them. They no longer filter on a scrape job: they match the metric names and the label `app`, the dashboard also filters by `slot`, and each alert fires for one app and slot.
- `edge`: `SlowLink` reports whether a request says its client is on a slow link: the query parameter `net=slow`, which a page adds to its stream's URL from its own measurement; `Save-Data: on`; Chromium's client hints, `ECT` of slow-2g, 2g or 3g, `RTT` over 300 ms or `Downlink` under 0.8 Mbit/s, which Chromium sends once a document has asked for them with `Accept-CH: ECT, RTT, Downlink` (`NetworkHints`).
- `live`: `Spec.Slow` marks a stream to a client on a slow link. It sends each view's newest frame 250 ms or more after the last, about four a second. A view's first frame goes out at once, and so does the frame of a view that sent nothing for 250 ms, which takes the frames that wait along: views that change together still arrive together, and an outcome is not held up. Heartbeats go out as before. On a phone with its CPU slowed four times on DevTools' Slow 4G and 3G presets, a tab of a Game of Life that steps ten times a second kept its main thread 54 to 56% busy instead of 89 to 90%, and its stream sent 2.7 to 2.9 KB/s instead of 5.2 to 6.2. A phone too slow for the page needs it on a fast link too: with the CPU slowed 15 times on an unthrottled link, the tab fell 94 to 98 s behind the board in five minutes without it, while the hub dropped no frame and no write waited, since the browser and the kernel held the frames; with it, the tab stayed within 1.2 s.
- `live`: a dirty view does not render while every stream that watches it still has a frame of it waiting. The first stream that takes its frame marks the view dirty again, and the next tick renders it as it is then, so a stream that falls behind sends the frame that waited, then the newest a tick later. A stream whose writes block costs no renders until its write deadline ends it, and a view that only slow streams watch renders about four times a second instead of at every tick: for 50 tabs with a view of their own that changes at every tick, 0.4 cores instead of 1.6 to 1.7 on slow streams, and 0.03 to 0.05 instead of 1.4 to 1.7 on streams whose client stopped reading. `Stats.RendersDeferred` counts the renders put off, and `lith/prom` exports it as `<namespace>_live_renders_deferred_total`. A view that one of its streams keeps up with renders at every change, as before.
- The template's page measures its link once as it starts, into `$_slow`: `navigator.connection`'s `saveData` or an effective type of 2g or 3g, or where that is missing, a document whose first byte came more than 300 ms after its request or that came at under 100 KB/s. Its stream then opens with `net=slow`, its documents send `Accept-CH`, and its stream handler sets `Spec.Slow` from `edge.SlowLink`.

## v0.2.0 (2026-10-14)

Streams are measured by memory: the budget books what each stream holds, sizes its window from its frames, and with `Refuse` caps the streams instead of a count. No API was removed. What to check in an app:

- A budget's `Limit` now covers each stream's encoder, 32 KiB besides and the frames the hub keeps, not only the encoders. The default, half the memory limit, needs no change; a `Limit` sized for encoders alone now lets fewer streams compress.
- `ZstdWindow` and `BrotliWindow` are the largest window a stream may get: each stream takes the smallest window that holds its frames. `MinWindow` no longer defaults to 18; set it only for pages whose frames refer back further than one write.
- With `Refuse`, a stream gets in only with room for a window that holds its frame, and its headers go out with its first frame. Open streams with `retry: 'error'` and leave `live.Options.MaxStreams` at its default, as a backstop.
- A view that one stream watches, such as a tab's own, no longer keeps its frame: a stream that joins it gets a frame rendered in the next tick.

- `sse`: `ReadSignals` reads a request's Datastar signals for any method: the `datastar` query parameter of GET, HEAD and DELETE, the JSON body of the others, `@query`'s QUERY included. It caps the body at 1 MiB (`ReadSignalsLimit` for another cap), takes a request without signals as none, and reads the body to its end, so that over HTTP/1.1 a handler that waits before it answers still notices a client that left. Called after `Open`, it returns `ErrBodyConsumed`.
- `edge`: `Compress` compresses the answers to QUERY as it does GET's.
- `sse`: `PatchElements` and the other events split HTML without a carriage return with `bytes.IndexByte`: a 230 KB page takes 40 µs instead of 342.
- `sse`: a budget books what its streams hold, not only their encoders: each stream's tier, 32 KiB for the rest of the stream (its state, its goroutines' stacks, net/http's buffers), and what `Budget.Hold` books, such as the frames a hub keeps. `Limit`, half the process's memory limit by default, now covers all of it; the other half stays for the rest of the app and for the garbage between collections. `BudgetStats.Frames` reports what `Hold` booked. Without `Refuse`, uncompressed streams may take the total beyond the limit.
- `sse`: a stream's tier is picked at its first write, from its largest write: the window must hold that frame with a sixteenth to spare, or a frame cannot refer to the one before. A brotli stream takes that window and no larger one, at quality 4 while the budget stays at most half full, then at quality 3, and only when that does not fit, quality 3 at 2^16, which compresses each frame alone; it goes out uncompressed only when even that does not fit. A zstd stream takes the largest tier within its fair share, moves down no further than its frame's window, takes 2^15 only when that window does not fit, and moves up again at a write once room frees up. `MinWindow` no longer defaults to 18: unset, the frames decide; set, it is the smallest window a stream's frames need, for pages whose frames refer back further than one write. With a limit, an unset `ZstdWindow` or `BrotliWindow` lets the budget go up to `MaxWindow`. In 150 MiB, 114 brotli tabs with a 230 KB view each hold 2^18, and 168 zstd tabs. The tiers are booked from measurements at 50 to 230 KB: brotli's 7 to 31% lower, zstd's 32 to 48 KiB higher. Apps that set `MinWindow` to their largest frame can drop it.
- `sse`: `Stream.Upgrade` returns a channel that the stream's budget closes when the stream holds a brotli window below its frames, or went out uncompressed, and a stream opened now would get a window that holds them: at most one stream a second. `BudgetStats.Reopened` counts them.
- `live`: the hub books the frames it keeps in the streams' budget, once for all the streams that watch a view: a `[]byte` frame at its length and 8 KiB, another by its `Len() int` method. A stream with `Spec.Reconnect` ends with `sse.Reconnect` when its budget has a better tier for it, and the page opens it again; the same stream ID at most once a minute, a stream without an ID after a minute.
- `live`: the hub keeps a view's newest frame only while two or more streams watch it. Of a view that one stream watches, such as a tab's own, it keeps the frame's length and hash once the stream has the frame: a render that repeats it still goes to no stream, the budget books nothing for it, and a stream that joins the view gets a frame rendered in the next tick. That saves about 235 KiB a tab with a 233 KB view of its own, 34 MiB for 150 such tabs, and a budget with `Refuse` no longer goes past its limit by the frame of a tab that `Open` has just let in. A frame that is not `[]byte` has no hash, and the hub keeps it as before. Each `[]byte` frame is hashed once as it renders, about 16 µs for 233 KB.
- `sse`: with `Refuse`, a budget lets a stream in only with room for 32 KiB and the smallest tier of its coding whose window holds its frame: `Options.Frame`, which `live`'s `Serve` sets from the stream's first frames (unset, the coding's smallest tier). It also turns away a stream that compresses nothing (its client accepts no coding, or `NoCompression` is set) when its 32 KiB do not fit. A stream let in keeps a window that holds its frame until it closes: a zstd stream keeps that tier booked before its first write and while it hibernates, and moves no lower when the budget fills or a lower limit asks it to; a brotli stream takes no window below its frame. When the budget turns a stream away, the zstd streams above their frame's window move down to it at their next write, until the stream would fit. A stream whose frames outgrow its window later keeps its tier and sends more bytes a frame until it gets a larger one; it is never cut off. So no stream the budget lets in goes out uncompressed, in raw blocks or with a window below its frame, and memory caps the streams: an app with `Refuse` leaves `live.Options.MaxStreams` at its default as a backstop, and its pages open their streams with `retry: 'error'`. In 120 MiB, 134 zstd tabs with a 233 KB view each get in, all at 2^18, or 91 brotli tabs, and the others get a 503. Before, 150 MiB let in 175 zstd tabs with a 230 KB view, most of them at 2^15 to 2^17, where a frame took 4 to 35 KB instead of about 60 bytes.
- `live`: `Serve` opens a stream once the first frames of its views are there, or the tick that renders them has ended, and gives their length to the budget (`sse.Options.Frame`), which with `Refuse` answers 503 when no window that holds them fits. The response's headers now go out with the first frame: on a hub that ticks every 50 ms, 24 ms later at the median, while the first frame comes as soon as before. A view that `Watch` gives a stream that the budget then turns away waits for the next stream with its ID, as it does while none is open.
- `prom`: `sse_budget_frames_bytes` and `sse_budget_reopened_total`; the limit and the reservation cover what the streams hold.
- `sse`: a brotli stream flushes its encoder every 16 KiB of a frame at quality 3 and every 32 KiB at 4. Without those flushes brotli extends a copy into the next input block without hashing it, so after a change in a large frame it lost the frame before and coded the rest in short pieces: a 230 KB board at quality 3 and 2^18 took 3,173 bytes a frame and now takes 259, a 230 KB data table that scrolls 5,756 and now 227 (quality 4: 2,382 and 140, 3,450 and 134). The encoder's heap no longer grows with the frame: at 230 KB, quality 3 at 2^18 held 1,554 KiB against the 1,312 its tier booked, and now holds 1,083; quality 4 at 2^18 2,370 against 2,192, now 1,603. Each flush costs a metablock header: a 230 KB list with 20 changes spread through it takes 676 bytes a frame instead of 363, and a 50 KB board at quality 4 50 instead of 34. The CPU per frame of a 230 KB frame changes by 13% less to 30% more.

## v0.1.1 (2026-10-14)

- `sse`: with `ZstdLowMemory` set and a memory budget (every `live` hub has one), a client that accepts brotli but not zstd, such as Safari, got its stream uncompressed: the low-memory filter dropped the brotli tiers too. It now narrows zstd's tiers only. Apps that set `ZstdLowMemory` should update.

## v0.1.0 (2026-10-13)

The first release: the runtime for Go, SQLite and Datastar apps, with a template for new apps, a skill for coding agents and the website at lith.zweiundeins.gmbh. It needs Go 1.27 and builds with `CGO_ENABLED=0`.

### Packages

- `sqlite`: one write connection and a `query_only` read pool; pragmas; migrations by `user_version` or a project's own runner; read-only opens; `View` and `ViewValue` in one snapshot, joining a transaction a ctx carries; `VACUUM INTO` backups. Each read connection keeps the 128 statements it ran last prepared.
- `writer`: the single writer. `Send`, `Do` and `DoValue` queue commands, which run in batches of one transaction with a savepoint each, on statements prepared once; `Once` and `OnceResult` for requests a client retries; `Flush`; `Exclusive` for work between batches; checkpoints and `PRAGMA optimize`.
- `live`: commits touch topics, topics mark views dirty, and each tick renders every dirty view once, in one read transaction per worker, for all the streams that watch it. Presence, `Every`, `Watch` and `Unwatch`, `WriteTick`, a stream cap, heartbeats, and `Spec.Reconnect`, which ends each stream with `sse.Reconnect` when the server stops, so that pages open their stream again on the next process.
- `sse`: Datastar's events, formatted once and written to many streams; zstd, brotli or gzip per stream, with a deadline on every write; a memory budget that shrinks the streams' windows as more open; idle streams that give their encoder back (`Hibernate`).
- `edge`: sessions, CSRF, the client's address behind a proxy, a CSP with a nonce, compression, precompressed static files, rate limiters, request logs, health checks.
- `tenant`: one open database per account, refcounted, evicted at a soft cap.
- `dbmetrics`: statement timing and a slow-query log through a wrapping driver.
- `loadtest`: the writer and the render loop under load, in process, without HTTP.
- `backup` (a module of its own): Litestream to S3, a restore when the file is missing, snapshots, a daily verify.
- `dbmetrics/prom` and `prom` (modules of their own): the statements', the writer's, the hub's and the stream budget's numbers in Prometheus.

### Defaults to know

- `synchronous=NORMAL`: a power loss or a kernel crash can undo the commits of the last 35 seconds or so; a crash of the process loses none. `sqlite.Options{Synchronous: "FULL"}` syncs every batch.
- The streams share a memory budget of half of GOMEMLIMIT, or of the cgroup's limit: a few streams compress with 512 KiB windows, many with 256 KiB, and the rest go out uncompressed, or not at all with `Refuse`.
- An idle stream keeps its encoder until `live.Options.Hibernate` is set.
- A page opens its stream with `retry: 'error'` from an element with an id, the one `Spec.Reconnect` names.

### Tools

- `cmd/lith-new` copies the template into a new module that requires the lith it ran from: a guestbook with tests, CI, a systemd unit, a Caddy block, a deploy script with rollback and a backup timer.
- `skills/lith`: the rules for coding agents, with review commands, Datastar notes, recipes and performance numbers.
- `bench`: the writer, render and stream benchmarks, with the commands to run them again (`bench/RESULTS.md`).

### Website

lith.zweiundeins.gmbh runs on lith, from `site/`: the landing page, the docs (guides that follow one app, Datastar notes, performance, the package reference from the doc comments, a review checklist and this changelog), and eight live demos: a guestbook, a writer race, a stream inspector, a pixel canvas, a shared board, a cursor party, a Game of Life and a million checkboxes.
